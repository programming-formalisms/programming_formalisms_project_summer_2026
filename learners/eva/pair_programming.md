# Notes on pair programming:

## What is pair programming?

Two people write code together on one machine (they not only write code but also plan and discuss their work)

## How does a good pair behave? Describe what can be observed when pairing online?

Pair splits up: 

* Driver (types, tactical, detail orientet) and Navigator (observer, reviewer, medium-term thinking)
* Ping (writes failing test) Pong (implementation so it passes)
* Strong-Style Pairing (for learning-by doing) with experienced person being navigator while novice is driver

## When to switch roles? Give a procedure

Pomodoro technique, pair rotations

## What effects does pair programming have?

* Knowledge sharing
* Reflection
* Focus
* Code review on-the-go
* Collective Code Ownership
* Two modes of thinking combined
* Fast onboarding
