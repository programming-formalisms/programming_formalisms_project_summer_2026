- Question 1: What is pair programming?
It's a job management system in which two people work on the same code with different roles.

- Question 2: How does a good pair behave? Describe what can be observed when pairing online
To look to change roles often, not distractions for the navigator,
the driver must summarize its work before changing the role.
If online, keep in mind to make the remote person being part of the team.

- Question 3: When to switch roles? Give a procedure.
For example, for somewhat fixed amounts of time like 4-5min.

- Question 4: What effects does pair programming have?
Knowledge transfer, better code with less bugs, its more efficient
to have someone looking for mid-term development (the navigator).
The main limitation is that the beggining of the project
is slower as it requires first to coordinate.
